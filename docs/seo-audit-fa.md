# گزارش ممیزی سئو — shik.app

- **تاریخ بررسی:** ۵ نوامبر ۲۰۲۶
- **دامنه:** https://shik.app
- **مخزن:** `cnc-parts-shop` — Next.js 16.2.11 (App Router) + Prisma/PostgreSQL
- **نسخهٔ بررسی‌شده:** `bef8d60` (آخرین کامیت؛ سئوی فاز ۱ در `bc35fab` ساخته و در `bef8d60` revert شده است)
- **روش:** بررسی سورس‌کد، بررسی ۲۱۱۴ URL سایت‌مپ، دریافت ۲۰۰۰ محصول از API عمومی، تست ۲۰+ URL زنده، بررسی `site:shik.app` در گوگل
- **محدودیت:** دسترسی به Google Search Console و GA4 در این بررسی وجود نداشت؛ بنابراین اعداد ترافیک، کلیک و نرخ کلیک بررسی نشده‌اند.

## ۱) خلاصهٔ مدیریتی

سایت از نظر زیرساخت فنی سالم است (HTTPS، ریدایرکت دامنه، sitemap داینامیک، JSON-LD پایه، RTL، فونت بهینه). اما **چهار سیگنال اصلی سئو اشتباه تنظیم شده‌اند** و همین باعث می‌شود زحمت ۲۱۰۹ محصول به نتیجه نرسد:

1. **کنونیکال همهٔ صفحات به صفحهٔ اصلی اشاره می‌کند** → گوگل صفحات دسته‌بندی، درباره‌ما، تماس و تعمیرات را نسخهٔ تکراری خانه می‌بیند.
2. **عنوان و توضیحات همهٔ صفحات لیست، یکسان است** → کلیک‌خوری و رتبه پایین.
3. **محصولات و لیست‌ها کلاینت‌ساید رندر می‌شوند** و صفحهٔ واقعی برای دسته/برند وجود ندارد → ۲۱۰۹ محصول و ۱۴۰ دسته، صفحهٔ فرود قابل رتبه‌گرفتن ندارند.
4. **داده‌های ساختاریافته قیمت را ۱۰ برابر اشتباه اعلام می‌کند** (تومان در برابر IRR) و موجودی را همیشه «موجود» نشان می‌دهد.

**تخمین:** فاز ۱ (بحرانی) با ۱ تا ۲ روز کار، بیشترین اثر را دارد و ریسک آن پایین است. فاز ۲ (صفحات دسته/برند) موتور رشد بلندمدت است.

## ۳) یافته‌ها

### 🔴 P0 — بحرانی

#### P0-1. کنونیکال همهٔ صفحات به صفحهٔ اصلی است
**شاهد (تست زنده):**

| URL | مقدار canonical |
|---|---|
| `https://shik.app/products` | `https://shik.app` ❌ |
| `https://shik.app/about` | `https://shik.app` ❌ |
| `https://shik.app/contact` | `https://shik.app` ❌ |
| `https://shik.app/repairs` | `https://shik.app` ❌ |
| `https://shik.app/products?category=hmi` | `https://shik.app` ❌ |
| `https://shik.app/products/<slug>` | خودش ✅ |

**علت ریشه‌ای:** `src/app/layout.tsx` خط ۲۷:

```ts
alternates: { canonical: "/" }
```

این مقدار در Next.js به همهٔ Routeهای فرزند ارث می‌رسد و هر صفحه‌ای که `alternates.canonical` خودش را تعریف نکند، به خانه canonical می‌شود. تنها صفحهٔ محصول چون `generateMetadata` اختصاصی دارد، سالم است.

**اثر:** گوگل صفحات مهم را به‌عنوان نسخهٔ تکراری خانه در نظر می‌گیرد؛ شانس ایندکس مستقل آن‌ها نزدیک صفر می‌شود. در `site:shik.app` هم می‌بینیم که گوگل در عمل canonical را نادیده گرفته و URLهای فیلتر را با عنوان تکراری ایندکس کرده است — یعنی هم اتلاف بودجهٔ خزش، هم محتوای تکراری.

**راه‌حل پیشنهادی:**
- حذف `alternates` از `src/app/layout.tsx`
- افزودن canonical اختصاصی در هر صفحه:
  - خانه: `/`
  - محصولات: `/products`
  - درباره/تماس/تعمیرات: مسیر خودشان
  - محصول: `/products/<slug>` (از قبل دارد)
  - دسته/برند (فاز ۲): `/category/<slug>`، `/category/<parent>/<sub>` و `/brand/<slug>`
  - صفحه‌بندی: canonical به همان صفحه با `?page=n` یا صفحهٔ ۱

#### P0-2. عنوان و توضیحات تکراری
**شاهد:** `/products`، `/about`، `/contact` و `/repairs` همه این‌ها را برمی‌گردانند:

- title: «شیک | شیک خرید کنید — فروشگاه تخصصی قطعات CNC و اتوماسیون صنعتی»
- description: «شیک خرید کنید | فروش تخصصی قطعات سی ان سی، موتور سروو، پی ال سی...»

در نتایج گوگل نیز `/products?category=hmi` و `/products?category=inverter` با همین عنوان عمومی دیده می‌شوند.

**علت:** فقط `src/app/layout.tsx` و `src/app/(main)/products/[slug]/layout.tsx` متادیتا دارند. هیچ‌کدام از صفحات `products`، `about`، `contact`، `repairs` متادیتای اختصاصی ندارند.

**راه‌حل:** برای هر صفحه `export const metadata` با title/description/OG یکتا. برای `/products` بهتر است با `searchParams`، عنوان دسته/برند انتخاب شود (یا در فاز ۲ به صفحات اختصاصی منتقل شود).

#### P0-3. رندر کلاینت‌ساید لیست‌ها + نبود صفحهٔ دسته/برند
**شاهد:**
- `src/app/(main)/page.tsx` و `src/app/(main)/products/page.tsx` هر دو `"use client"` هستند.
- در HTML اولیهٔ `/products`: **هیچ `<h1>` وجود ندارد** و لینک محصولی دیده نمی‌شود؛ محصولات بعد از اجرای JS از `/api/products` بارگذاری می‌شوند.
- در HTML اولیهٔ خانه: **هیچ لینک `/products/<slug>` وجود ندارد**.
- فیلترها فقط با query param کار می‌کنند: `?category=`، `?sub=`، `?brand=`، `?q=`، `?sort=`.
- ۱۴۰ دسته و ۳۴ برند هیچ URL اختصاصی ندارند.
- گوگل URLهای `?category=` را ایندکس کرده است (نمونه: `products?category=hmi`, `?category=coupling`, `?category=gd10`).

**اثر:**
- محتوای اصلی صفحات لیست برای خزنده در دسترس نیست.
- همهٔ نسخه‌های فیلترشده، محتوای تکراری با متادیتای یکسان تولید می‌کنند.
- ۱۴۰ + ۳۴ صفحهٔ فرود بالقوه (دسته/برند) از دست رفته‌اند؛ اینها معمولاً بهترین کلمات کلیدی تراکنشی («خرید اینورتر دلتا»، «قیمت سروو موتور») را می‌گیرند.

**راه‌حل (فاز ۲):**
- ساخت `/category/[slug]` (و زیردسته به‌صورت تو در تو: `/category/<parent>/<sub>`) و `/brand/[slug]` به‌صورت Server Component با:
  - `generateMetadata` یکتا
  - `<h1>` و متن معرفی اختصاصی
  - گرید محصولات رندر‌شده در سرور
  - صفحه‌بندی با لینک واقعی
  - `BreadcrumbList` با URL واقعی
- تبدیل `/products` به Server Component (با `searchParams`) و نگه‌داشتن تعاملات در کامپوننت‌های کوچک کلاینت.
- ریدایرکت ۳۰۱ از `?category=<slug>` به `/category/<slug>` (و مشابه برای برند) در صورت نبود پارامترهای دیگر؛ در غیر این صورت canonical به صفحهٔ دسته.
- استفاده از کد موجود در کامیت `bc35fab` (فقط بخش سئو، نه تغییرات تم/لودینگ) به‌عنوان نقطهٔ شروع.

#### P0-4. robots.txt و صفحات خصوصی
**شاهد:** `robots.txt` فقط `Allow: /` دارد و این صفحات با کد ۲۰۰ و `index, follow` پاسخ می‌دهند:

`/admin`، `/profile`، `/cart`، `/auth/login`، `/api/products?limit=1`

**اثر:** صفحات نازک/خصوصی ایندکس می‌شوند، بودجهٔ خزش هدر می‌رود و ریسک ایندکس‌شدن صفحات ادمین وجود دارد.

**راه‌حل:**
- `export const metadata = { robots: { index: false, follow: false } }` در لایوت/صفحات `admin`، `auth`، `cart`، `profile`
- افزودن به `src/app/robots.ts`:
  ```ts
  disallow: ["/admin", "/api", "/cart", "/profile", "/auth"]
  ```
- توجه: برای صفحات خصوصی، `noindex` مؤثرتر از `Disallow` است (چون خزنده باید صفحه را ببیند تا noindex را بخواند). بهتر است هر دو اعمال شود ولی مسیرهای حساس در robots بسته شوند.

### 🟠 P1 — مهم

#### P1-1. داده‌های ساختاریافته (Schema) نادرست
**شاهد روی صفحهٔ محصول BK25:**
- قیمت نمایش‌داده‌شده: `۱۱٬۷۸۵٬۶۲۸ تومان`
- در JSON-LD: `"priceCurrency": "IRR"`, `"price": "11785628"`
- `"availability": "https://schema.org/InStock"` در حالی که `stock: 0`
- برای محصولات بدون قیمت (۳۳۹ مورد)، `Offer` بدون فیلد `price` تولید می‌شود → خطای «Missing field price» در Rich Results
- `sku` برای هیچ محصولی وجود ندارد

**علت:** `src/app/(main)/products/[slug]/page.tsx` → ساخت `productLd`:
- تبدیل تومان به ریال انجام نمی‌شود (۱۰ برابر اختلاف)
- `availability` ثابت است
- `offers` حتی وقتی `price` صفر/تهی است ساخته می‌شود
- `sku` از `product.sku` می‌آید که در دیتابیس خالی است

**اثر:** ریسک جریمه/نادیده‌گرفتن داده ساختاریافته، نمایش قیمت اشتباه در نتایج گوگل و Google Shopping، از دست رفتن rich result.

**راه‌حل:**
```ts
const priceRial = product.price > 0 ? Math.round(product.price * 10) : null;

const offers = priceRial
  ? {
      "@type": "Offer",
      url: `${SITE_URL}/products/${slug}`,
      priceCurrency: "IRR",
      price: String(priceRial),
      availability: "https://schema.org/InStock",
      itemCondition: "https://schema.org/NewCondition",
      seller: { "@type": "Organization", name: "شیک" },
    }
  : undefined; // اگر قیمت نداریم، offers را حذف کن
```
- اگر موجودی واقعی نگهداری می‌شود، `availability` را بر اساس `stock` تنظیم کن؛ در غیر این صورت `InStock` را حفظ کن ولی در گزارش بنویس که stock قابل اتکا نیست.
- `sku`: از `product.sku ?? product.legacyGoodId ?? product.slug` استفاده کن.
- `image`: آرایهٔ همهٔ تصاویر، نه فقط تصویر اصلی.

#### P1-2. سایت‌مپ ناقص و بدون encode
**شواهد:**
- ۲٬۱۱۴ URL: فقط ۵ صفحهٔ ثابت + محصولات. **هیچ دسته یا برندی در سایت‌مپ نیست.**
- URLهای فارسی به‌صورت خام (Unicode) نوشته شده‌اند؛ استاندارد sitemap, URL percent-encoded می‌خواهد.
- URLهای ثابت `lastModified` ندارند.
- `sitemap-images.xml` فقط ۱٬۸۵۵ محصول را دارد (۲۵۴ محصول تصویر اصلی ندارند) و هدر `cache-control: no-store` دارد.
- محصولات با `active: false` درست حذف شده‌اند ✅

**راه‌حل:**
- افزودن دسته‌ها (فقط دسته‌های دارای محصول) و برندها
- `encodeURI` روی اسلاگ‌ها
- `lastModified` برای صفحات ثابت (یا حذف فیلد)
- `revalidate` مناسب روی image sitemap به‌جای `no-store`
- اگر تعداد از ۵۰٬۰۰۰ گذشت، تقسیم به sitemap index (فعلاً لازم نیست)

#### P1-3. لینک‌سازی داخلی ضعیف
**شاهد:** در HTML اولیهٔ خانه هیچ لینکی به صفحهٔ محصول نیست (بارگذاری کلاینت‌ساید). لینک‌های دسته در هدر/فوتر فقط ۲ دسته را پوشش می‌دهند (`inverter`, `linear-guide`) و به query param می‌روند.

**اثر:** خزنده مسیر رسیدن به ۲٬۱۰۹ محصول را فقط از سایت‌مپ دارد؛ ارزش لینک داخلی توزیع نمی‌شود و صفحات عمیق کشف نمی‌شوند.

**راه‌حل (فاز ۲):** رندر سرور محصولات پرفروش/جدید در خانه، لینک به ۲۳ دستهٔ اصلی در فوتر، breadcrumb لینک‌دار، و «محصولات مرتبط» در صفحهٔ محصول.

#### P1-4. کش ۲۴ ساعتهٔ صفحهٔ محصول
`export const dynamic = "force-static"` + `revalidate = 86400` در `products/[slug]/page.tsx`.
- قیمت/موجودی تا ۲۴ ساعت قدیمی می‌ماند و می‌تواند با Schema و واقعیت نخواند.
- `page.tsx` و `layout.tsx` هر دو `getProduct` را جدا صدا می‌زنند (دو کوئری یکسان).

**راه‌حل:** استفاده از `unstable_cache`/`cache()` برای تابع `getProduct`، و کاهش `revalidate` به ۳۶۰۰ ثانیه یا استفاده از `revalidatePath` بعد از ویرایش محصول در ادمین.

#### P1-5. ساب‌دامین `dl.shik.app` و کش تصاویر
- ریشهٔ `dl.shik.app` صفحهٔ پیش‌فرض پارس‌پک را نشان می‌دهد و در `site:shik.app` ایندکس شده است.
- تصاویر `dl.shik.app` هدر `cache-control` ندارند (در حالی که Vercel Blob دارد).
- در `public/uploads` حدود **۸۰ مگابایت** فایل قدیمی وجود دارد که در پروداکشن ۴۰۴ می‌دهند.

**راه‌حل:** حذف/جایگزینی صفحهٔ پیش‌فرض ساب‌دامین + `noindex`، تنظیم کش CDN برای تصاویر، حذف `public/uploads` از مخزن و افزودن به `.gitignore`.

### 🟡 P2 — محتوا و عملکرد

#### P2-1. محتوای نازک
- ۲۴۵ محصول بدون تصویر
- ۲۵۳ محصول بدون توضیحات
- ۴۸۰ محصول با توضیح کمتر از ۱۲۰ کاراکتر
- ۳۳۹ محصول بدون قیمت

این صفحات در مقیاس ۲٬۱۰۹ صفحه، کیفیت کلی دامنه را پایین می‌آورند. پیشنهاد: یا محتوا/تصویر تکمیل شود، یا موقتاً `noindex` شوند تا کیفیت میانگین بالا بماند.

#### P2-2. عنوان‌های بلند
۱٬۲۲۵ محصول عنوان بلندتر از ۷۰ کاراکتر دارند (مثلاً نام کامل + برند + مدل + «اورجینال وارداتی»). گوگل عنوان را کوتاه می‌کند و CTR پایین می‌آید.

**راه‌حل:** الگوی عنوان کوتاه‌تر: «<نام کوتاه> <مدل> | شیک» و انتقال جزئیات به description.

#### P2-3. تصاویر و Core Web Vitals
- ۱۵ مورد `<img>` خام (به‌جای `next/image`)
- بزرگ‌ترین فایل‌ها: ۱٫۹MB، ۱٫۶MB، چند فایل ۱٫۱MB
- فرمت‌های JPG/PNG بدون نسخهٔ WebP/AVIF و بدون `srcset`

**راه‌حل:** `images.remotePatterns` برای `dl.shik.app` و Vercel Blob، مهاجرت تدریجی به `next/image`، تولید WebP، preload تصویر LCP.

#### P2-4. تاکسونومی
- ۱۴۰ دسته شامل زیردسته‌های «زیر ۱ کیلووات»، «۱٫۵ کیلووات»، «۳ تا ۴ کیلووات» که در واقع فیلتر مشخصه‌اند نه دسته.
- برند «غیره» با ۱۵۵ محصول برای صفحهٔ برند مناسب نیست.
- ۱ دستهٔ خالی («کالاهای نرم‌افزار حسابداری (تاریخی)»).

**راه‌حل:** تصمیم بگیر کدام‌ها صفحهٔ فرود مستقل بگیرند (پیشنهاد: فقط دسته‌های دارای ≥۵ محصول و برندهای واقعی)؛ بقیه در فیلتر بمانند و `noindex` شوند.
